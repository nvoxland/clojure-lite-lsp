// clojure-lite-lsp

A Clojure language server small enough to run in every worktree.

Working with coding agents means many codebases open at once: several projects, several worktrees of each, an editor or an agent in every one. clojure-lite-lsp uses about 20 MB per editor, and a new worktree indexes only the files that differ from ones already indexed. It stays that small by implementing only the parts of the language server protocol for reading and reviewing code. With an agent making the edits, the features for writing code by hand are left out.

// what it does

Small per project

Each editor's server uses about 20 MB. Libraries are indexed once for the machine, and a new worktree only indexes the files that differ from ones already indexed.

Reading and review

Go to definition and declaration, find references, implementations of protocols and multimethods, hover docs, file outlines, symbol search, call hierarchy, occurrence highlighting and argument hints.

No editing features

No completion, diagnostics, formatting, rename, refactorings or code actions. Editors see the server doesn't offer them and don't show them.

Agents

Claude Code uses it through its LSP tool, Codex through MCP, and any agent through clojure-lite-lsp query. clojure-lite-lsp setup configures a project for them.

Editors

Extensions for VS Code and Zed. Any other editor with an LSP client can run clojure-lite-lsp lsp.

Command line

clojure-lite-lsp query answers the same questions in a terminal or a script: definitions, references, callers, callees, docs.
